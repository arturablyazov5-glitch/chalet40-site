# Chalet40 — Astro / Таймвеб

Node.js >=22.23.4, npm; статический RU/EN-сайт, 46 контентных HTML и 404. Все цены — локальные типизированные данные; Google Sheets в runtime не используется. Срок сдачи подтверждён заказчиком: **3 квартал 2028**, одна константа `src/data/site.ts`.

```sh
npm ci
npm run dev -- --port 4322
npm run check
npm run i18n:check
npm test
npm run build
```

Dev: http://127.0.0.1:4322/. Порт 4321 может быть занят другим проектом. RU без префикса, EN — `/en/` и `/en/...`. `/en/` — единственная форма в canonical, hreflang и sitemap. `/en` остаётся совместимым адресом без обязательного редиректа; другие исходные пути не меняются. Полная политика `/privacy` индексируется, sitemap.xml — полный urlset, sitemap-index.xml также доступен.

Privacy перенесена дословно с подготовленного текста **другой компании — hitdev.ru / ООО «Хайтэк Девелопмент»**. Она сохраняет исходные домен, оператора, адрес почты и неполную фразу в п. 8.5. Нужна юридическая вычитка под chalet40.moscow; это не подтверждение применимости документа. EN политики, остальных текстов и унифицированной терминологии — черновик на вычитку.

## Консультация и dev

Контракт: POST `/api/consult`, `Content-Type: application/json`, тело `{name, method: "whatsapp"|"phone"|"telegram"|"max", contact, consent: true, lot?, lotTitle?, page, lang, utm?, company?}`. Ответ: `{ok:true}` либо `{ok:false,error}`. `lot` — id офиса или P/K парковки, до 64 символов. Однострочные поля не принимают управляющие символы. UTM: только utm_source, utm_medium, utm_campaign, utm_term, utm_content, до 200 UTF-16 units каждое. lotTitle — необязательное понятное название из словаря текущего языка, до 80 UTF-16 units; без него выводится id. HTML сообщения, включая теги и сущности, ограничен 4096 UTF-16 units, поля аккуратно усекаются. Общий запрос — до 8192 байт. Honeypot company, включая строку `"0"`, возвращает формальный успех без transport.

По умолчанию dev **не отправляет сообщения**, даже если `.env` содержит token/chat_id. Для гарантированно offline режима:

```sh
TELEGRAM_DEV_SEND=0 npm run dev -- --port 4322
```

Для ручной реальной проверки **только пользователем**, после проверки адресата и согласованных тестовых данных:

```sh
TELEGRAM_DEV_SEND=1 npm run dev -- --port 4322
```

TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID берутся из `site/.env` либо окружения; переменные процесса имеют приоритет. Не вставляйте значения в команды, URL, скриншоты или тикеты. `.env` игнорируется git и должен иметь 0600. Изменили схему/секреты/флаг — перезапустите dev. При включённом режиме и отсутствующей/невалидной конфигурации — JSON 503, при отказе Telegram — 502; форма не объявляет ошибку успехом. В этой задаче реальная отправка не выполнялась.

Production принимает только Origin `https://chalet40.moscow`, dev — собственный loopback Origin и порт; cross-site и Origin null запрещены. Для offline HTTP-проб явно передавайте соответствующий Origin; отсутствие CORS не является антибот-защитой. Telegram вызывается только сервером с parse_mode=HTML и отключённым preview ссылок. Компактная карточка менеджера: имя, способ связи/действие, понятное помещение и корпус, ссылка с путём без домена (полный адрес в href), язык и московская дата/время отдельными строками, UTM. Без эмодзи и символов-иконок; корпус/этаж — словами, неизвестный корпус не выводится. Разрешены только b, a href, code; пользовательские значения экранируются (PHP htmlspecialchars ENT_QUOTES|ENT_SUBSTITUTE UTF-8). Ссылки генерируются только на HTTPS/tel/mailto; номер и действие не образуют вложенные code/link-сущности. Каноническая спецификация — src/data/consult-message.json, копируется в dist/api/message-format.json при build. PHP использует api/telegram-message.php; dev — src/lib/telegram-message.ts. Golden-тесты и независимый JS-эквивалент PHP сверяют фиксированные входы/выходы; PHP-интерпретатор при этих проверках не запускался.

Лимит: 5 валидных попыток за 60 секунд на REMOTE_ADDR; при 429 есть Retry-After. На сервере состояние — в приватном `sys_get_temp_dir()/chalet40-consult`, каталог 0700, файлы 0600. Под одной глобальной блокировкой выполняются чтение/запись и очистка файлов старше суток (проверка раз в минуту); повреждённое состояние, ошибка блокировки/записи/fflush → 503, без отправки. Сетевой запрос выполняется после освобождения блокировок. Убедитесь, что PHP видит реальные IP через доверенную настройку reverse proxy: произвольный X-Forwarded-For приложение не использует.

cURL: connect timeout 5 с, общий 12 с, TLS verification включён. Клиент ждёт 20 с, автоматического повтора нет; данные при отказе сохраняются. При таймауте/обрыве заявка могла быть доставлена — уточните у отдела продаж перед повтором. Очередь и idempotency в текущий контракт не входят.

## Генерация секретного PHP config

После последней сборки:

```sh
npm run config:php
```

Команда читает `.env`, атомарно создаёт **dist/api/config.php с 0600** и выводит предупреждение «файл содержит секрет, грузить только на сервер». Значения не печатаются. Без `.env` либо непустых корректных переменных — понятная ошибка. Файл не попадает в исходники; dist/ игнорируется git. Следующая сборка очищает dist — **повторите config:php после build**. Не открывайте/копируйте секретный config в отчёты; передавайте только по защищённому каналу на сервер. Пустой config.example.php остаётся шаблоном, если конфиг создаётся вручную на сервере.

## Деплой на Таймвеб

1. Выполнить check/i18n:check/test/build, затем config:php. Проверить наличие index.html, 404.html, sitemap.xml/индекса, robots.txt, обоих `.htaccess`. В комплекте не должно быть `.env`, src, node_modules, `.map`, backup/архивов/дампов. `api/config.php` — единственное осознанное секретное исключение, права 0600. Проверка git history/secret scan выполняется в настоящем checkout без вывода секретов.
2. Нужны Apache 2.4, mod_rewrite, mod_headers, mod_deflate/mod_filter и AllowOverride для Options, FileInfo, AuthConfig/Require. PHP **>=8.1** с cURL, CA bundle и исходящим HTTPS к api.telegram.org:443. Встроенный PHP-сервер не читает `.htaccess`; локальный Astro не доказывает правила Apache.
3. Таймвеб может отдавать статику через **Nginx, минуя Apache/.htaccess**. Права/заголовки/сжатие/запреты для таких URL необходимо обеспечить настройкой frontend тарифа/через поддержку и проверить извне. `.htaccess` не является обещанием защиты файла, который frontend отдал самостоятельно. Не загружать backup/config-копии — основная защита от такой утечки. [Документация Таймвеба](https://timeweb.com/ru/docs/virtualnyj-hosting/obshchaya-informaciya-o-hostinge/osobennosti-tekhnicheskogo-resheniya/).
4. Подключить chalet40.moscow к правильному document root (обычно public_html), сертификаты bare + www. Одну канонизацию HTTP/www → HTTPS bare настроить в панели/на frontend. Не добавлять слепую проверку HTTPS off за reverse proxy; не доверять клиентскому XFF/X-HTTPS. Проверить HTTP/HTTPS × www/bare без циклов, с сохранением пути/query. Принятые адреса RU/EN не переводить массово на слеши. `.htaccess` обслуживает `/en/` и совместимый `/en` внутренне одним HTML.
5. Загрузить **содержимое site/dist/**, включая скрытые `.htaccess` в корне и api/. Каталоги обычно 0755, обычные файлы 0644; config.php 0600, читается PHP под UID владельца. Не chmod 777. Если UID другой — минимально необходимая группа/режим только по согласованной настройке хостера. RateDir должен быть вне public_html, доступен с open_basedir и принадлежать PHP UID.
6. PHP: display_errors=Off, log_errors=On, закрытый error_log вне public_html. В приложении Throwable закрывается общим JSON и статическим кодом события; не логируются payload, контакты, token/chat_id, Telegram response и tokenized URL. Parse error основного файла требует отдельного PHP lint на среде с PHP. Proxy timeout — с запасом, не менее 30 с; TLS verification не отключать.
7. Бот должен быть запущен в целевом чате или добавлен в группу с правом отправки. Проверку конфигурации/доставки делает владелец самостоятельно после готовности хостинга; не подменять рабочий config ложным токеном для негативного теста. Для отказных тестов использовать transport stub без внешней сети.
8. Повторная выкладка: новые хешированные assets сначала, HTML после; старые assets не удалять немедленно. Секретный серверный config сохранять отдельно, не использовать rsync --delete без исключений. Иметь предыдущий комплект и защищённую серверную копию config для отката.

## Заголовки и контроль после выкладки

В `.htaccess` закрыты config*, скрытые сегменты (исключение — ACME challenge) и `.map`; листинг отключён. HTML — revalidate, хешированные /_astro — год immutable, нехешированные assets — час, API — no-store. Gzip включается при наличии модулей и корректных MIME, проверяется Content-Encoding/Vary. На Nginx эти правила требуют отдельного контроля.

CSP **Report-Only** генерируется при каждой сборке по точным байтам финальных inline-script, без unsafe-inline/unsafe-eval; font/img/connect — self (для img также data), object/frame запрещены. Referrer-Policy, Permissions-Policy, nosniff, X-Frame-Options включены. Report-Only видна в консоли, серверный сбор отчётов не настроен. Перед заменой на enforced CSP проверить все страницы, карту, SVG-паркинг, форму, переключение лотов и шрифты; после любой сборки хеши пересчитываются автоматически. [CSP Level 3](https://www.w3.org/TR/CSP3/).

Приёмка на реальном frontend (локально PHP/Apache отсутствуют и не устанавливались):

- Чистые RU/EN URL и обе формы EN-главной: 200, правильный canonical; случайный путь — настоящий 404, без soft-404.
- config.php, config.example.php, config.php.bak, config.old.php, .env, скрытый путь и .map: 403/404, никогда исходник. Canary-тест backup делать с безвредным файлом на staging.
- API: GET → 405 + Allow: POST; чужой/missing Origin → 403; MIME → 415; invalid JSON → 400; >8192 → 413; поля → 422; шестая попытка → 429 + Retry-After. Honeypot `"0"` не вызывает transport.
- Offline transport: success, отказ Telegram, timeout, invalid response; отсутствующий/сломанный config, read-only/full/corrupt state — общие JSON 502/503, без отладочного вывода. Параллельные PHP workers не обходят квоту.
- Реальные разные IP за proxy, cache/security headers на 200/404/405/502, gzip/Vary для HTML/CSS/JS/fonts. CSP и функциональность в браузере.
- Затем одна согласованная владельцем контрольная заявка и подтверждение получения в Telegram; все методы RU/EN, выбранный lot/page, сохранение формы при отказе.
